# BAWCode

芝士一个一个一个一个终端 AI 编码 Agent，使用python实现，使用OpenAI兼容协议


## 神奇功能

- **模型路由**：providers 按模型归属自动路由
  api_key/base_url，plan/review/code 等角色可各自配模型，配了不同模型工作流回合内就能多模型协作；
  思考链回显、温度、思考强度等参数可按提供商逐个调
- **代码检索RAG插件**：tree-sitter 按代码块切片，类/函数/注释优先召回，当前固定走
  关键词模式，embedding 已停用但向量代码仍保留；建好索引后随用户消息主动注入
- **工具结果全生命周期管理**：超过单条行内上限的完整输出立即外置，行内留截断预览与取回路径；
  普通维护跳过不足 128 字符的短文本，未超限的最近结果、白名单等受保护结果继续留原文，
  超龄结果再整理成摘要并外置。图片也会限量保留并缩小，上下文预算按模型窗口自动算，
  `/context` 可看明细——目前来看上下文的管理效果还是不错的
- **防误删机制**：删除安全护栏默认开启，识别成功的 shell 删除命令会被拦截，能解析目标的尝试移入项目回收站，执行/clear-trash才彻底清空；严格模式下部分命令只拦截不搬移，搬移失败会明确报告，/security off 可关闭护栏。只有捕获到文件或发现外部改动才写回合快照，空回合不产生快照，会话树里可撤回文件和会话到某一轮消息
- **工作流引擎**：可自定义工作流管线，自行配置提示词等各项参数，同时为llm提供了调用链路
- **插件系统**：提供了一套可能较丰富的接口可供插件调用，可以做各种神奇小插件
- **远程控制**：可以通过内置WebUI的插件进行远程控制
- **摇人干活**：task 工具异步派发子代理，后台跨回合并行跑，完成通知自动唤醒主Agent
- **食食物着为俊杰**: 情绪插件能够自动识别用户情绪，想骂gai时让AI哄一下你的情绪

## 内置插件

插件都住在 `data/plugins/`：

| 插件 | 功能 |
|------|------|
| `rag` | 使用tree-sitter按语言为代码块切片，类/函数/注释优先召回，当前固定关键词模式，建好索引后主动注入上下文 |
| `remote-control` | 能够在浏览器中随时随地实时操作终端，或者说是个WebUI |
| `qbridge` | 作为一个消息适配器使用 |
| `emotion-detector` | 用户消息情绪识别，情绪不佳时让AI主动哄你 |
| `web-search` | 必应网络搜索工具：关键词 → 真实浏览器头请求结果页 → 结构化结果：标题/链接/摘要 |
| `music-player` | 终端音乐播放器，作为TUI显示接口的例子 |
| `computer-use` | GUI 自动化 |
| `ask-user-subagent` | 让Agent将对AI来说很困难的任务交给你 |
| `hello-plugin` / `bottom-banter` | 两个示例插件，写插件时可以直接抄 |

RAG 首次使用要先执行 `/rag build`，或让 Agent 调用 `rag_index` 工具建立索引；没有索引时不会主动召回。索引落盘持久化，后续只重建有增改的部分。embedding模式由于需求不对应，暂未支持。

## 安装与运行

```bash
pip install -r requirements.txt
pip install -e . #项目目录下执行，装完在任意目录敲 bawcode 即可启动
python main.py #启动TUI
python main.py -p "构建AGI，务必做好"  # 无头模式，跑完即退；加 --json 输出机器可读结果
```

无头模式还可用 `--cd <目录>` 指定工作区、`--config <路径>` 指定配置文件。默认没有真人确认通道，需要人工确认的工具会自动拒绝；要让这类调用在无人值守时直接放行，需要加 `--full` 切到完全访问。

## 输入说明
- **@ 引用文件**：输入 `@` 会弹出工作区文件补全（tab确认），选中后消息发出时文件内容直接进上下文，模型看得见原文
- **Ctrl+V 粘贴**：超长文本自动折叠成占位符；图片落盘后按多模态消息发送。短文本直接全文嵌入，二进制或超大文件会引用路径
- **发送**: Enter 发送，Shift+Enter 换行。回合进行中enter发送是插话，会在下一工具轮边界并入;ctrl+enter是排队到下一回合开始时提交
- **会话回退**：fullscreen 模式下 Tab 切焦点到会话树，方向键翻节点，Ctrl+Z 截断回退到选中的消息，紧接着再按一次可撤销回退；inline模式仅支持/undo回退
- **节点树**：思考链和正文逐块直播渲染成节点树，部分节点会自动折叠，可使用alt+t展开思维链，alt+o展开工具节点，alt+e展开所有节点

## 设置面板

`/settings` 打开，PgUp/PgDn 翻页，双击x重置当前整个标签页。

**访问模式**（Shift+Tab 快捷切换）：

| 模式 | 行为 |
|------|------|
| confirm | 安全声明工具和项目白名单直接放行，其余每个工具调用都弹窗请求审批 |
| edit | 在 confirm 基础上 write/edit_file 编辑类工具直接放行 |
| auto | 安全工具、白名单、编辑类直放，无法确认安全性的交由llm审批 |
| full | 权限层全放行；删除护栏开着时，识别成功的删除命令仍会被拦截改入回收站 |

**上下文管理**：

- **自动压缩 + 压缩阈值**：上下文占用超过可用输入预算的n%（默认0.8，预算扣除输出预留和安全余量）就触发压缩管线，旧消息切成结构化摘要，保留尾段token数可调（保留尾段一些历史记录以减小中途压缩带来的影响）
- **激进上下文优化**：每次请求前执行一次**回合末上下文整理**
- **历史思考保留条数**：每轮请求只带最近N条思考链，更旧的留档不发。不同服务提供商可能有不同的接受方式。verbatim为保留思考链字段回传（如Deepseek）、merge为拼接思考链内容到正文中、strip为不回传思考内容（默认）
- **保留图片读取张数 / 读图缩放长边**：限量保留原图+读前缩小

**安全**：

- **删除安全护栏**：默认开启；识别成功的 shell 删除命令会被拦截，能解析目标的尝试移入项目回收站。`/security off` 关闭后会直接执行删除
- **严格删除护栏**：连 `git clean`、`find -delete`、`python -c "os.remove..."` 这类删除也拦；其中无法可靠解析目标的命令只进行拦截

**其他常用**：

- **人格提示词**：在`data/system_prompt/*.md` 里可选择系统人格，可自行添加人格文件，下回合生效
- **渲染模式**：fullscreen 是全屏会话树，inline是终端原生滚动
- **LLM 重试/超时**：429/5xx/网络错误的重试次数、间隔与单次请求整体超时
- **空转计数上限**：模型重复无进展输出计满 N 次就终止回合，防止吃白饭
- **默认命令执行器**：支持cmd / git bash / powershell，指定后只改变默认执行方式，模型仍然可以指定使用的执行器

## 运行流程

一个回合的完整流程（`core/loop.py` 的 tool_loop）：

```
输入消息，同时RAG尝试召回并且拼入消息、@ 引用展开
  → 装配请求：系统提示词 + 历史 + 计划/步骤 + 工具定义
  → 模型流式返回：正文 / 思考链 / 工具调用
  → 有工具调用：权限判定
    → 执行 → 结果进上下文 → 回到模型，进入下一轮
  → 没有工具调用：回合结束，回合末整理上下文，Runner 落盘保存
  →（激进压缩开启情况下）执行回合末上下文整理，进入下一轮
```
**补充**：
- 更具体的上下文处理情况：超过行内上限的工具输出立即外置；短文本、最近结果和白名单等受保护结果优先留原文，超龄结果再外置成摘要；图片限量；老思考链归档；快接近窗口时触发压缩管线把老消息变摘要。易变内容（计划/步骤）拼接在消息队尾以优化缓存命中率
- RAG代码检索（`data/plugins/rag`）：用 tree-sitter 按语言语法把代码切成类/函数级小块，连注释和 docstring 一起提取；发送消息时按关键词召回最相关的几块，直接拼接进用户消息一起发给模型。需要先用 `/rag build` 或 `rag_index` 工具手动简历索引，每次扫描会重解析有变化的文件。
- **快照与回收站**：捕获到文件或发现外部改动时才写回合快照，空回合不产生快照，被外部改过的文件会跳过。删除护栏默认开启，能可靠解析目标的删除命令才尝试移入项目回收站，严格模式下部分命令只拦截，护栏关闭后删除命令会直接执行
